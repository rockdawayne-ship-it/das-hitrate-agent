# DAS 히트율 시뮬레이터 -- PRD (Product Requirements Document)

> 생성일: 2026-10-04
> 생성 도구: CoreMate_PRD (Show Me The PRD 기반)

---

## 1. 제품 개요

### 한 줄 요약
출고 데이터(`data.xlsx`)를 올리면 DAS 웨이브와 토트 수를 계산해 히트율(OL/TOTE, PCS/TOTE)을 보여주고, DAS 셀 수·토트 용량·주문 단위를 바꾼 시나리오들을 나란히 비교해 주는 내 PC용 웹 도구.

### 해결하는 문제
- 히트율을 구하려면 엑셀에서 피벗 → 웨이브 번호 입력 → 조회 수식 → 피벗 → 값 붙여넣기를 여러 단계로 해야 하고, 수십만 행 파일은 계산에 오래 걸린다.
- 웨이브 번호를 손으로 매기는 과정에서 날짜 경계 등에서 실수가 생기기 쉽다.
- "DAS 셀을 24칸으로 늘리면?", "토트 용량이 20이면?", "배송처차수 대신 배송처로 묶으면?" 같은 질문에 답하려면 엑셀 작업을 처음부터 다시 해야 한다.

### 핵심 가치
- **규칙대로 자동 계산**: 웨이브 묶음·토트 계산 규칙(4장)을 코드로 고정해 손 작업과 실수를 없앤다.
- **설정 비교가 한 화면에**: 시나리오 여러 개의 히트율·토트 수·작업량을 표와 차트로 나란히.
- **한 번 읽고 계속 사용**: 큰 엑셀은 처음 한 번만 읽어 저장, 이후 시나리오 계산은 수 초.
- **데이터가 밖으로 안 나감**: 로그인·서버 없이 내 PC(localhost)에서만 실행.

## 2. 사용자

### 주요 사용자
- **누구**: DAS(분배) 공정의 운영 기준·설비 규모를 검토하는 물류 실무자 1명 (본인)
- **상황**: 설비 증설·운영 기준 변경을 검토하거나 보고 자료를 만들 때, 사무실 PC에서
- **목표**: 현재 설정의 히트율을 확인하고, 설정을 바꿨을 때 토트 수·히트율이 얼마나 달라지는지 숫자로 비교

### 사용자 시나리오
1. 사용자가 `data.xlsx`(1년치 출고, 약 65만 행)를 끌어다 놓으면 열이 자동 인식되고(배송처차수 → 주문, Order Line → 오더라인) 저장된다.
2. 기본 시나리오(DAS 16셀·토트 15PCS·배송처차수·10시간)의 KPI 카드와 일·월 히트율 추이가 나온다.
3. "16셀 / 24셀 / 32셀" × "토트 15 / 20" 시나리오를 추가하고 계산을 누르면
4. 비교 표에서 "24셀·20PCS면 기준 대비 토트 X% 감소, OL/TOTE Y"를 확인하고 결과를 엑셀로 내보낸다.

## 3. 입력 데이터

`data.xlsx` 시트 `data` (1행 머리글). 열 이름으로 찾으므로 순서는 상관없다.

| 열 | 의미 | 예시 | 사용 |
|----|------|------|------|
| 실확정일자 | 출고 확정일 (YYYYMMDD) | 20250102 | 날짜 구분 |
| 검토기준 | 상품 그룹 | 의류용품 | Phase 2 필터 |
| 배송처차수 | 배송처 코드 + 공백 + 차수 | 14247 301 | 주문 키 |
| 상품코드 | SKU | FS3CPG4309XBLK000 | 토트 계산 |
| Order Line | 오더라인 수 | 1 | 합계 |
| PCS | 수량 | 4 | 합계·토트 계산 |

- 규모: 약 65만 행, 1년(약 245 영업일), 파일 약 18MB (압축 해제 시 시트 XML 약 165MB)
- 다른 형식 파일(예: `배송처코드`, `O/L` 열)도 열 매핑으로 처리할 수 있어야 한다.

## 4. 계산 정의

> 이 정의가 제품의 핵심이다. 코드·화면·엑셀 출력 모두 이 표 하나를 따른다.

| 항목 | 정의 |
|------|------|
| 주문(order) | 시나리오의 주문 단위 값 1개 = DAS 셀 1칸. 기본: `배송처차수` 전체("14247 301") / 대안: 배송처(공백 앞부분 "14247") |
| 웨이브 | **날짜별로** 그날의 고유 주문 키를 **문자 오름차순** 정렬해 DAS 셀 수만큼 차례로 묶고 1, 2, 3…을 매긴다. 날짜가 바뀌면 1부터 다시. |
| 토트 | (날짜, 웨이브, 상품코드)별 PCS 합계를 토트 용량으로 나눠 **올림**: `ROUNDUP(PCS 합 / 토트 용량)` |
| order / sku | 날짜별 고유 주문 수 / 고유 상품코드 수. 기간 합계 행은 기간 전체 고유 수 |
| order line / pcs | 날짜별 Order Line 합 / PCS 합 |
| tote | 날짜별 토트 합 |
| HIT RATE OL/TOTE | order line ÷ tote |
| HIT RATE PCS/TOTE | pcs ÷ tote |
| 보조 지표 | Order/OL = order line ÷ order, Order/PCS = pcs ÷ order, OL/PCS = pcs ÷ order line, OL/SKU = order line ÷ sku |
| 시간당 | tote/h = ROUNDUP(tote ÷ 작업시간), PCS/H = pcs ÷ 작업시간 |
| 평균(AVG) | 0·빈 값을 뺀 날짜별 값의 단순 평균 |
| 기간 히트율 | 기간 합계 기준 (Σorder line ÷ Σtote). 날짜별 히트율의 평균과 구분해서 표시 |

### 계산 예시 (수작업 정답 — 테스트에 그대로 사용)

DAS 셀 2, 토트 용량 15, 날짜 하루:

| 주문 키 | 상품 | Order Line | PCS |
|---------|------|-----------|-----|
| A 101 | X | 1 | 10 |
| A 102 | X | 2 | 20 |
| A 102 | Y | 1 | 1 |
| B 201 | X | 1 | 16 |

- 정렬: "A 101", "A 102", "B 201" → 웨이브 1 = {A 101, A 102}, 웨이브 2 = {B 201}
- 토트: 웨이브1·X = ROUNDUP(30/15)=2, 웨이브1·Y = ROUNDUP(1/15)=1, 웨이브2·X = ROUNDUP(16/15)=2 → **tote 5**
- order 3, order line 5, pcs 47, sku 2 → **OL/TOTE 1.00, PCS/TOTE 9.40**
- 주문 단위를 "배송처"로 바꾸면: 주문 {A, B} → 셀 2이므로 웨이브 1 하나 → X = ROUNDUP(46/15)=4, Y = 1 → **tote 5**, order 2

## 5. 핵심 기능

| 기능 | 설명 | 우선순위 | 복잡도 |
|------|------|----------|--------|
| 업로드 + 열 자동 인식 | .xlsx/.csv, 시트 선택(대소문자 무시), 열 자동 매핑(배송처차수/배송처코드, Order Line/O/L), 수동 수정 | P1 | 간단 |
| 대용량 읽기 + 저장 | 수십만 행 엑셀을 빠르게 읽어 DuckDB에 저장, 같은 파일 재업로드 감지 | P1 | 보통 |
| 계산 엔진 | 4장 정의대로 웨이브·토트·날짜별 결과 계산 | P1 | 보통 |
| KPI 카드 + 추이 | OL/TOTE, PCS/TOTE, 총 토트, 일평균 / 일·월 히트율 추이 차트 / 날짜별 표 | P1 | 간단 |
| 시나리오 비교 | DAS 셀 수·토트 용량·주문 단위·작업시간 조합 여러 개를 계산해 기준 대비 증감 비교 | P1 | 보통 |
| 엑셀 내보내기 | 시나리오별 날짜 결과 시트(비율은 엑셀 수식) + 비교 시트 + 설정 시트 | P1 | 간단 |
| 특이일 표시·제외 | 주문 1건인 날, OL/TOTE < 1인 날 표시, 평균에서 제외 옵션 | P2 | 간단 |
| 기간·검토기준 필터 | 특정 기간, 검토기준별 계산 | P2 | 보통 |
| 날짜 드릴다운 | 특정 날짜의 웨이브별·SKU별 토트 상세 | P2 | 보통 |
| 웨이브 묶음 방식 비교 | 코드 순 묶음 외에 SKU가 겹치는 주문끼리 묶는 방식 등 비교 | P3 | 복잡 |

## 6. 사용자 흐름 (User Flow)

### 핵심 흐름
```
실행 -> 파일 업로드 -> 열 확인 -> 저장 -> 기본 결과(KPI·추이)
     -> 시나리오 추가 -> 계산 -> 비교 표·차트 -> 엑셀 내보내기
```

### 상세 흐름
1. **실행**: `streamlit run app.py` → 브라우저에 열림.
2. **업로드**: 파일 선택 → 시트 선택(여러 개면) → 열 자동 매핑 표시(주문 단위 열은 사용자가 확인) → 저장(진행 표시).
3. **기본 결과**: 데이터셋 선택 → 기본 시나리오 KPI 카드, 일·월 추이 차트, 날짜별 표.
4. **시나리오**: 표에서 시나리오 행 추가(이름, DAS 셀, 토트 용량, 주문 단위, 작업시간) → "계산" → 진행 표시.
5. **비교**: 기준 시나리오 대비 총 토트·OL/TOTE·PCS/TOTE·tote/h 증감 표 + 월별 OL/TOTE 비교 차트.
6. **내보내기**: 선택한 시나리오의 날짜 결과 + 비교 + 설정을 한 엑셀로.

## 7. 성공 기준

- [ ] 4장 계산 예시(주문 단위 2종)를 포함한 수작업 정답 테스트가 모두 통과
- [ ] 엑셀로 직접 만든 1일치 계산(피벗+ROUNDUP)과 같은 날의 도구 결과가 모든 열에서 일치
- [ ] data.xlsx(65만 행) 업로드·저장 90초 이내, 저장된 데이터로 시나리오 1개 계산 15초 이내
- [ ] 시나리오 6개(셀 3종 × 토트 2종) 비교를 클릭 3번 이내로 실행
- [ ] 내보낸 엑셀을 열었을 때 수식 오류 셀 0개, 시트의 합계가 화면 KPI와 일치

## 8. 안 만드는 것 (Out of Scope)

> 이 목록에 있는 건 Phase 1에서 만들지 않습니다.
> AI에게 코드를 시킬 때 이 목록을 함께 공유하세요.

- 로그인/사용자 관리 -- 이유: 혼자 내 PC에서 쓰는 도구
- 웨이브 묶음 최적화 -- 이유: 기본 규칙 계산이 먼저. Phase 3에서 비교 방식으로 추가
- 실시간 WMS 연동 -- 이유: 데이터 원천은 엑셀 내보내기
- 작업자 인원·설비 비용 계산 -- 이유: 이번 범위는 히트율·토트 수까지
- 계산 규칙 임의 변경(정렬 기준, 올림 방식) -- 이유: 4장 정의가 기준. 바꾸려면 PRD 개정
- 클라우드 배포 -- 이유: 출고 데이터가 외부로 나가지 않도록 로컬 유지

# DAS 운영 분석 에이전트

출고 엑셀·CSV를 읽고 DAS 셀 수와 토트 용량에 따른 토트 수·히트율을 비교하는 **내 PC용 앱**입니다. Ollama는 질문을 계산 계획으로 바꾸고, 숫자와 결과 설명은 PRD에 따라 계산한 값에서 생성합니다.

## 바로 실행

1. 이 폴더의 **Start-DAS.cmd**를 더블클릭합니다.
2. 브라우저에서 **http://127.0.0.1:8516**이 열립니다.
3. **데이터 준비 → 파일 선택 → 열 확인 → 검증하고 저장**을 진행합니다.
4. **시나리오 비교 → 계산**을 누르면 기본 6개 조합을 비교합니다.
5. **에이전트와 대화**에서 질문하거나 **엑셀 생성 → 다운로드**를 사용합니다.

앱을 종료하려면 **Stop-DAS.cmd**를 실행합니다. 브라우저 탭을 닫아도 서버는 실행 상태를 유지합니다. 저장한 데이터는 종료 후에도 남습니다.

## 화면 없이 쓰기 (배포 불필요)

| 방법 | 어떻게 |
|---|---|
| 더블클릭 실행 | `run_app.bat` 또는 바탕화면 바로가기 "DAS 히트율 시뮬레이터". 서버를 띄우고 브라우저를 연다. 창을 닫으면 종료 |
| 명령줄 (CLI) | `das.cmd datasets / register <파일> / kpi / compare [--export] / ask "<요청>" [--llm claude]`. `--json`으로 기계 판독 출력 |
| Claude Code 스킬 | 이 폴더에서 `claude` 실행 후 `/das 기본 6개 비교해줘`. 스킬이 CLI를 호출해 엔진 결과를 그대로 보고 (`.claude/skills/das/SKILL.md`) |
| 사내 공유 | 내 PC에서 실행 중이면 같은 네트워크에서 `http://<내 PC IP>:8502`. 방화벽 8502 인바운드 허용. 로그인이 없으니 신뢰 네트워크에서만 |

DuckDB는 한 프로세스만 연다. 앱이 떠 있으면 CLI는 `저장소를 열 수 없습니다`로 멈추므로 앱을 닫거나 `--data-dir`로 다른 폴더를 쓴다.

## 실제 데이터 위치

추천 파일 경로:

```text
%USERPROFILE%\DAS_Data\input\data.xlsx
```

입력 폴더는 생성되어 있습니다. 파일을 이 위치에 넣으면 **추천 폴더의 data.xlsx 불러오기** 버튼으로 읽을 수 있습니다. 다른 위치의 파일도 업로드할 수 있습니다.

실제 데이터가 없으면 **합성 샘플 파일 생성 → 검증하고 저장**으로 체험하세요. 합성 샘플은 실제 출고 실적이 아닙니다.

- 필수 열: 실확정일자, 배송처차수, 상품코드, Order Line, PCS
- 선택 열: 검토기준
- 별칭: 배송처코드, O/L, 수량 등은 자동 매핑 후 수정할 수 있습니다.
- 잘못된 날짜·빈 주문 키·수량 오류는 행 번호와 함께 표시합니다.
- 주문 키와 SKU는 문자열로 읽어 원본에 있는 앞자리 0을 보존합니다.
- OL·PCS는 0~1,000,000,000의 정수입니다. 음수 반품·소수 수량은 저장을 중단합니다.
- 동일 파일·시트·열 매핑·정규화 버전이면 저장 데이터를 재사용합니다.

## 대화 예시

정형 요청은 빠른 규칙 해석으로 처리합니다.

- “기본 6개 비교해줘”
- “16·24·32셀과 토트 15·20PCS를 비교해줘”
- “배송처로 다시 계산”
- “2025-01-01 ~ 2025-03-31 기간으로 계산”
- “전체 기간으로 다시 계산”
- “결과를 엑셀로 내보내줘”

Ollama가 필요한 표현도 사용할 수 있습니다.

- “셀을 두 배로 늘리면 어떻게 돼?”
- “셀 수를 현재의 세 배로 바꾸고 토트는 그대로 유지하면?”
- “토트 용량을 지금의 두 배로 늘려서 비교해줘”

계산 계획과 도구 실행 기록을 결과 아래에서 확인할 수 있습니다. 목적이 모호하거나 입력값이 잘못되면 되묻습니다. 일반 목적의 자유 대화 챗봇은 후속 API 연동 단계입니다.

## 모델 연결

현재 기본값은 **Ollama / qwen3:30b-a3b**(MoE, 약 19GB, RTX 5090 24GB에 전량 GPU 적재)입니다. 이 PC에서 모델 설치와 실제 요청 검증을 완료했습니다. VRAM이 작은 PC는 `DAS_OLLAMA_MODEL=qwen3:4b`(2.5GB)로 바꿉니다. 모델 서버에 연결할 수 없으면 앱은 정형 요청 모드로 계속 사용할 수 있습니다.

다른 PC에서는 Ollama를 설치·실행한 뒤 한 번 내려받습니다.

```powershell
ollama pull qwen3:30b-a3b
```

모델을 설치한 후 앱의 **모델 연결 다시 확인** 버튼을 누릅니다. 원하면 사이드바에서 **정형 요청 · 모델 없음**을 선택할 수 있습니다.

앱의 Ollama 연결은 localhost로 제한됩니다. 프록시 환경변수나 외부 API로 자동 전환하지 않습니다.

### Claude 구독 사용 (선택)

사이드바 "대화 모드"에서 **Claude 구독 · Claude Code 로그인**을 고르면 Claude Code CLI(`claude -p`)를 구독 계정으로 호출합니다. API 키·종량 과금이 없고 Pro/Max 구독 사용량에 포함됩니다. 모델은 `DAS_CLAUDE_MODEL`(기본 `sonnet`, 별칭 `opus`·`fable` 가능).

```powershell
npm install -g @anthropic-ai/claude-code
claude auth login
claude auth status
```

전송 범위: 현재 설정(셀·토트·주문 단위·작업시간)·데이터 기간·검토기준 값·사용자 요청문. 출고 원본 행과 집계 수치 표는 보내지 않습니다. PRD의 "데이터가 밖으로 안 나감" 조건을 엄격히 지켜야 하면 로컬 AI(Ollama)를 유지하세요. 호출은 MCP·설정·도구·CLAUDE.md를 모두 끈 경량 모드라 요청당 약 800 입력 토큰입니다. Anthropic API 키 직접 호출 경로는 제공하지 않습니다(`DAS_LLM=anthropic`은 모델 없음으로 동작).

참고: [Ollama 공식 모델 페이지](https://ollama.com/library/qwen3:30b-a3b), [구조화 응답 API](https://docs.ollama.com/api/chat).

이 PC에는 문맥 8,192 토큰·생각 모드 끔·요청 후 10분 메모리 유지를 적용했습니다. 모델 적재 후 합성 정답 데이터의 한국어 요청 3건은 모두 통과했고, 전체 처리 시간은 1.34~1.83초였습니다. 최초 적재와 실제 데이터 처리 시간은 다를 수 있습니다. [PC별 설정 및 측정 기록](docs/05_OLLAMA_PROFILE.md)을 확인하세요.

## 저장 위치

| 구분 | 위치 |
|---|---|
| 소스·설계 문서 | 현재 DAS_HitRate_Agent 폴더 |
| 원본 업로드 사본·DuckDB·엑셀 결과 | %LOCALAPPDATA%\das_hitrate |
| 실행 환경·서버 로그·검증 기록 | %LOCALAPPDATA%\DAS_HitRate_Agent |
| 실제 입력 권장 폴더 | %USERPROFILE%\DAS_Data\input |

운영 데이터는 Google Drive 작업 폴더에 자동 저장하지 않습니다. 사용자가 다운로드 위치로 동기화 폴더를 선택하는 경우에는 해당 폴더의 동기화 설정이 적용됩니다. Windows Store 방식 Codex 실행 환경에서는 앱 데이터 경로가 패키지의 LocalCache로 리디렉션될 수 있으며, 실제 경로는 사이드바의 **저장 위치·계산 버전**에서 확인할 수 있습니다.

## 적용한 계산 기준

- 날짜별 고유 주문 키를 문자순 정렬하고 셀 수만큼 묶어 웨이브를 배정합니다. 날짜마다 1부터 다시 시작합니다.
- 날짜·웨이브·SKU의 PCS를 먼저 합산한 뒤 토트 용량으로 나누어 올림합니다.
- 기간 주문·SKU는 기간 전체 고유 수입니다.
- 기간 히트율은 합계의 비율, 일평균은 0·빈 값을 제외한 날짜별 값의 평균입니다.
- 기간 시간당 지표는 총량을 출고일 수 × 일 작업시간으로 나눕니다.
- 분모 0은 N/A입니다. 데이터 없는 날은 자동으로 0인 날짜를 만들지 않습니다.
- 배송처 단위는 배송처차수의 첫 공백 앞 문자열을 사용합니다.
- 특이일(주문 1건인 날, OL/TOTE<1인 날)은 합계·기간 비율에 항상 포함합니다. 사이드바 "특이일을 일평균(AVG)에서 제외"를 켜면 AVG에서만 빠지고, 포함·제외 일수를 화면·설명·엑셀(`AVG(특이일 제외)` 행)에 표시합니다.
- 음수·소수 수량은 입력 오류로 저장을 중단합니다(조용히 제외하지 않음). 완전 중복 행은 삭제하지 않고 건수만 보고합니다.
- 기본 비교는 16/24/32셀 × 15/20PCS, 작업시간 10시간입니다.
- 비용·인력·이동거리 최적화는 범위에 포함되지 않습니다.

## 모듈 구조와 향후 API 연결

```text
app.py                 화면·입력·대화 상태
das_agent/
  agent.py             요청 해석·계획 검증·후속 요청·도구 실행
  llm.py               LLMProvider 계약, OllamaProvider, NullProvider
  tools.py             파일 검사·등록·시뮬레이션·비교·보고서 도구
  ingestion.py         파일 읽기·열 매핑·검증
  engine.py            PRD 웨이브·토트·히트율 계산
  storage.py           로컬 DuckDB·실행 결과·재사용
  reporting.py         결과 설명·수식과 캐시값을 갖춘 엑셀
```

외부 API는 llm.py의 공급자 계약을 구현해 추가할 수 있습니다. 계산 엔진과 파일 처리 코드는 교체할 필요가 없습니다. 자세한 연결 지점과 전송 범위 결정 항목은 [API 확장 안내](docs/04_API_EXTENSION.md)에 정리했습니다.

## 검증

2026-10-07, 엔진 1.1.0 기준:

- PRD 정답 2종, 날짜 경계·문자 정렬·기간 고유 수·올림·AVG 검사
- 입력 오류·앞자리 0·필터 해제·기준 선택·후속 요청·캐시 이름 검사
- 엑셀 캐시값 대조 및 LibreOffice 재계산 후 수식 결과 대조
- Streamlit 화면에서 샘플 등록 → 비교 → 엑셀 → 후속 요청 흐름 검사
- Ollama 실제 상대값 요청 3종 검사
- 합성 650,000행·245일·17.61MB XLSX: 읽기·검증·저장 **8.405초**, DB 로딩 포함 시나리오 계산 **1.943초**

위 성능은 이 PC의 합성 데이터 측정값입니다. 실제 출고 파일과 수작업 1일치 정답 대조는 아직 수행하지 않았습니다.

엔진 1.2.0 추가 검증 (2026-10-07):

- 1일치 정답 대조(PRD 성공 기준 2)를 합성 1일치로 대체: 엔진 / 손 절차(순수 파이썬) / 엑셀 수식(LibreOffice 재계산) 3중 대조, 전 열·주문 단위 2종 일치 — `tests/test_golden_day.py`, `sample_data/`
- 특이일 AVG 제외·분모 0 N/A·음수 거부 — `tests/test_outliers.py`
- 65만 행 합성 파일 end-to-end 도구 경로 성능 — `scripts/perf_650k.py` → [docs/07_PERF_650K.md](docs/07_PERF_650K.md)
- 미확정 항목의 현재 결정과 실데이터 확인 목록 — [docs/06_DECISIONS.md](docs/06_DECISIONS.md)
